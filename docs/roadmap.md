# GVideo Roadmap

本文记录 GVideo 的公开开发方向。具体实现范围以对应 Issue 和 Pull Request 为准，优先保证现有功能、数据与部署契约稳定。

## 近期目标

### 前端模块化

- 继续按 `app -> features -> shared` 依赖方向推进 Feature-first 迁移。
- 将评论、视频列表和创作者工作台从应用组合层拆分为独立功能模块。
- 收敛共享组件、API 类型和页面状态处理，减少跨功能耦合。

### 后端可维护性

- 在现有包边界内按职责拆分 HTTP、Service 和 Repository 大文件。
- 保持领域错误、权限规则和事务边界可独立测试。
- 补充媒体任务失败恢复、并发处理和数据迁移测试。

### 产品体验

- 改进搜索、分区浏览、投稿管理和通知中心的使用效率。
- 完善移动端导航、视频播放和字幕选择体验。
- 持续检查浅色与深色主题的一致性、可访问性和响应式布局。

## 中期方向

- 将媒体文件迁移到 S3 或 MinIO 兼容对象存储。
- 在多实例写入成为实际需求后，将 SQLite 迁移到 PostgreSQL。
- 将转码任务拆分为可独立扩展的 Worker。
- 增加可配置的推荐策略、审核工具和运营数据能力。

## 暂不计划

- 在单机部署仍能满足需求时拆分微服务。
- 在没有明确业务需求前引入复杂消息队列或搜索集群。
- 为追求目录形式而进行高风险全仓重写。

## 参与方式

开发建议和功能请求请提交 GitHub Issue。准备贡献代码前，请阅读 [贡献指南](../.github/CONTRIBUTING.md) 和 [架构说明](architecture.md)。
