# GVideo 工程案例

> 面向面试官与协作者的工程叙事：做了什么、难在哪里、怎么验证。
> 术语以 [CONTEXT.md](../CONTEXT.md) 为准，关键取舍记录在 [docs/adr/](adr/)。

## 一句话

可部署的视频社区全栈项目：Go 后端（模块化单体）+ React 前端 + HLS 转码管线 + HTTPS 网关，以 30 个分批交付完成从功能开发到安全、运维与架构治理的完整闭环。

## 数字概览

| 指标 | 数值 |
| --- | --- |
| 后端代码 | 16,557 行（其中测试 9,107 行，测试占比 55%） |
| 前端代码 | 4,460 行（React + TypeScript + Vite） |
| 领域模块 | 4 个纵向模块 + 进程内事件总线（notifications / comments / interactions / moderation） |

| CI | Ubuntu 环境后端 race 检测 + 前端构建/测试 |
| 交付批次 | 30 个（每批：实现 → 目标验证 → 只读复审 → 显式暂存 → 提交 → 推送） |

## 架构一览

```
浏览器 ── HTTPS 网关(nginx 443) ── 前端源(nginx: SPA + 静态资源)
                                      └── 反向代理 ── Go 后端(chi)
                                                        ├── 垂直模块 ×4 + 事件总线
                                                        ├── 媒体管线(ffprobe/ffmpeg/HLS)
                                                        └── SQLite(单写节点, WAL)
```

- **后端**：模块化单体，模块 = repository / service / handler 三层 + HTTPPort 协议端口；模块生产代码禁止反向依赖核心，由架构守卫测试强制（[ADR-0005](adr/0005-incremental-module-extraction.md)）。
- **跨模块协作**：类型化进程内事件总线，订阅者在发布方 goroutine 内联执行，通知写路径收敛为单一所有者（[ADR-0003](adr/0003-in-process-event-bus.md)）。
- **数据层**：SQLite 单写节点 + 启动时自动迁移与迁移前备份门禁；备份、校验、合并、授权走 `gvideo data-*` 命令（[ADR-0001](adr/0001-sqlite-single-writer.md)）。
- **安全边界**：网关与前端源分工下发安全响应头，任一响应每个安全头恰好一份（[ADR-0004](adr/0004-security-header-single-value.md)）；请求速率限制按可信代理解析客户端地址；每用户存储配额按源视频 + 封面 + HLS 实际产出计量。

## 三个难题与解法

### 1. 管理员提权漏洞：从"实时比较"到"持久标志"

**问题**：管理员身份由「用户名等于配置的 ADMIN_USERNAME」实时比较决定。任何能注册或改名到保留用户名的路径都等于直接获得管理员权限，大小写变体与数据合并还会放大这个问题。

**解法**：迁移 v2 引入 `users.is_admin` 持久标志作为唯一裁决依据；保留用户名仅在尚无管理员时可一次性认领（认领后即锁定），此后注册与改名一律拒绝，大小写变体同样拒绝；数据合并时标志随用户携带，并发认领由数据库层 `NOT EXISTS(admin)` 守卫保证只能成功一次；新增 `gvideo data-grant-admin` 作为显式授予通道，并在启动时校验与告警。

**验证**：迁移测试、保留名注册/改名用例、大小写变体用例、合并携带标志用例；升级路径写入文档。

### 2. 代理路径的重复安全头：一次运行态实证发现的隐患

**问题**：HTTPS 网关侧早已实现"隐藏上游同头副本、边缘统一重加"，但前端源 nginx 的 server 级 `add_header` 会继承进所有代理 location，与后端中间件自产的安全头叠加——实测 `/api`、媒体与健康端点每个头出现两份，两种不同 CSP 并存。

**解法**：SPA 头集只在前端自己服务的内容上下发；代理路径改为纯透传后端单份头（保留 deny-all CSP）；网关继续负责其自产响应并在转发时去重。

**验证**：修复前后运行态 curl 对照；新增 e2e 断言六类响应（SPA 文档、SPA 回退、theme-init、API、健康端点、媒体 404）的单值与精确 CSP 文本，防止回归。

### 3. 通知写路径收敛：三份镜像 INSERT → 事件总线

**问题**：评论与互动产生通知的写入逻辑散落在核心 service 与两个模块中（三份镜像 INSERT），一致性靠人肉同步，模块越多同步成本越高。

**解法**：新增类型化同步事件总线，notifications 模块 repository 成为互动与评论类通知写路径的唯一所有者；发布方经消费方自定义 `EventPublisher` 接口发布事件，不反向依赖核心；通知写失败只告警，不影响主请求。

**验证**：跨模块集成测试以真实总线断言「发布事件 → 通知落库」的端到端行为；迁移全程保持行为不变（自评抑制、空值防护随迁）。

## 工程方法

- **分批交付纪律**：每一批都走 实现 → 目标验证 → 独立只读复审 → 显式暂存（禁止 `git add .`）→ 提交 → 推送 的串行流程；批次边界与证据记录在 [development-handoff.md](development-handoff.md)。
- **证据边界**：验证结论必须标注范围（跑过什么、没跑什么），静态门禁、端到端与运行态证据分开记录。
- **文档体系**：handoff（会话延续与队列）＋ ADR（决策与被拒替代方案）＋ CONTEXT.md（领域词表，供人与 agent 共用）。
- **架构守卫**：用测试而非约定维持模块边界，让"边界漂移"在 CI 里变成红灯。

## 演进路线

- **当前（P1）**：发布打包——演示资产、工程案例、v1.0.0 与 release notes；维护队列（配额可观测性、容器降权、历史数据清理、OpenAPI、依赖扫描）按需触发。
- **下一步（P2）**：新方向立项（用 `/grill` 拷问流程定域与技术栈）。
- **分布式演进（P3）**：Redis 分布式限流与缓存 → 事件总线迁移 Outbox + 消息队列（至少一次投递、幂等消费、死信队列）→ 转码 worker 出进程与对象存储 → PostgreSQL → 容器编排与跨队列链路追踪。整体对应 ADR-0001/0002/0003 记录的回退路径与触发信号。
